# Безопасность

Warp-Manager выполняет установку от root и запускает отдельные клиенты WARP. Используйте доверенный исходный код. Независимый аудит и инфраструктура подписанных релизов не заявлены; SHA-256 проверяет целостность относительно доверенного источника.

## Сообщить об уязвимости

Используйте **Security → Report a vulnerability**, если владелец включил приватные сообщения об уязвимостях. Иначе создайте issue с нечувствительным описанием и запросите приватный канал. Не публикуйте SSH-данные, регистрации WARP, ключи, cookies и необезличенные runtime-снимки. Выдуманного адреса поддержки и обещанного SLA нет.

## Границы доступа

- SOCKS/HTTP не имеют собственной аутентификации и предназначены для loopback/контролируемой частной сети. Публичная привязка запрещена; приватная сеть требует контроля доступа со стороны администратора.
- Backend-порты доступны только на loopback. YouTube требует loopback. Правила Xray экспортируются и не применяются к панели автоматически.
- Проверки идут через выбранный SOCKS без намеренного прямого fallback. `SERVING` — анонимная проба, а не гарантия для аккаунта.
- Регистрации хранятся в отдельных Docker volumes. Обновления их сохраняют; удаление по умолчанию тоже. Явный purge удаляет локальные volumes.
- Runtime-файлы и очередь запросов имеют ограниченные права. Старые наблюдения не восстанавливаются как текущие READY.
- Внутри контейнера есть блокировка и таймаут ротации. Администратор root/Docker всё равно контролирует систему; от владельца VPS эта программа не изолирует.

## Загрузка компонентов

Cloudflare устанавливается из официального подписанного APT-репозитория и запускается с `--accept-tos`. Дополнительные curl-impersonate и Compose проверяются по закреплённым SHA-256 до выполнения; существующий Compose fallback не перезаписывает.

GitHub-bootstrap определяет commit по HTTPS, показывает сумму codeload ZIP, проверяет пути, размеры и синтаксис перед установкой. Сам bootstrap и выбранный репозиторий остаются доверенными источниками. Для HTTPS ZIP через CLI нужна ожидаемая сумма. SHA файла релиза отличается от суммы GitHub codeload-архива.

CI имеет только чтение репозитория: без SSH-секретов, развёртывания, регистрации WARP и автоматической публикации Releases. Actions закреплены commit SHA. Для сообщений об ошибках используйте последнюю проверенную версию и безопасное воспроизведение. Лицензии — в [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).
