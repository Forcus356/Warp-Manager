# FAQ

## Почему не получается выбрать Германию / NL / США в WARP?

Менеджер фильтрует наблюдаемый Google-регион. WARP не предоставляет используемый здесь эквивалент Psiphon EgressRegion или PIN конкретного сервера. Сохранённая регистрация не закрепляет публичный IP навсегда.

## Почему Cloudflare показывает DE, а Google — RU?

Это разные наблюдения. Политика Google проверяется по YouTube GL и, для Gemini, анонимному ответу модели. Cloudflare trace подтверждает WARP и адрес для этого запроса, а не регион Google.

## `SERVING` означает, что мой аккаунт точно работает?

Это положительный результат анонимной пробы скрипта. Доступность аккаунта также может зависеть от его настроек и реального клиентского пути. `INCONCLUSIVE`, CAPTCHA и HTTP 200 со страницей приложения не заменяют положительный модельный ответ.

## YouTube RU означает отсутствие рекламы и 4K без задержек?

`RU VERIFIED` означает наблюдаемый GL=RU. Порог скорости — короткая измеряемая проба; ни рекламное поведение, ни длительное воспроизведение браузером не сертифицируются этим статусом.

## 10 Гбит/с и десять туннелей по 1 Гбит/с гарантируют 10 Гбит/с?

Цель задаётся в Гбит/с, но её подтверждает только общий одновременный замер. Туннели могут делить CPU, канал VPS, маршрут и ограничения тестового узла. Сумма независимых замеров не гарантирует общую полосу. Один TCP-сеанс остаётся на одном выходе.

## Что означает дополнительная треть?

После набора рабочего состава создаётся `max(1, floor(N/3))` проверенных резервов: 10+3, 30+10, 1+1. Резерв не участвует в новых пользовательских соединениях до повышения в рабочие. После отказа он заменяет выход, а поиск восполняет запас.

## Можно ли запустить 99 × 128 туннелей?

Это предел адресации и схемы конфигурации. Он не был проверен как физическая вместимость сервера. На тестовом 1-vCPU/2-GiB VPS восемь WARP прошли нагрузку до 64 клиентов; гигабит и 128 реальных клиентов без ошибок не подтверждены.

## Почему `active` есть, а готовых узлов нет?

Systemd запустил монитор. Проверка транспорта/Google/Gemini/скорости выполняется отдельно. После рестарта предыдущий `SERVING` не считается текущим без повторной проверки.

## Почему `check` вернул 0, хотя Gemini не SERVING?

Команда поставила задачу в очередь. Результат смотрите в `status`/`logs`; это не синхронный код успешности Google.

## Почему большой нагрузочный тест останавливается?

Проверяйте `failed_clients`, ресурсный запас и состояние транспорта. Тестовый узел может возвращать HTTP-ошибки даже напрямую. Локальный TLS-генератор делит CPU с туннелями. Не выдавайте завершённый прогон с ошибками за успешную нагрузку.

## Почему адрес для IPv4 и IPv6 может различаться?

Прокси с удалённым DNS выбирает адрес назначения внутри WARP; `curl -4` при SOCKS5h ограничивает локальное соединение с прокси, а не обязательно семейство конечного адреса. Отправка исходного IP из Xray и отправка домена могут дать разный путь. См. [интеграцию Xray](xray/README.md).

## Зачем внутренние имена warp-google-pool, если репозиторий Warp-Manager?

Пути, volumes, службы и команда `warp-pool` сохранены для совместимости установок 0.2–0.4.1. Имя нового репозитория не требует потери регистраций или перенумерации портов.

## Где однострочное обновление из GitHub?

После публикации standalone bootstrap можно запускать с `--update --instance N`. Для проверенного ZIP используйте CLI `update SOURCE --sha256 DIGEST`. Автоматического поиска последнего GitHub Release в меню нет.
